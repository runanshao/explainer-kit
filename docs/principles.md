# 原理

> 往原理去理解，随后一通百通；可交付、可重复、稳定输出，才是 AI 赋能的前提。

这份文档讲 explainer-kit 为什么是现在这个样子。只记组件用法，换一个需求就得重新问；把下面几条原理弄明白，新需求多半能自己推出来，也能判断 AI 写的代码对不对。

## 一条主线

```
旁白稿 ──gen.py──▶ 逐词时间戳 ──timeline.ts──▶ 帧号 ──场景(纯函数)──▶ 画面
  [[cue]]          timings.json            c() w() rel()      f ↦ 像素

短片稿 ──────────▶ 节拍网格 ───────grid.ts────▶ 帧号 ──场景(纯函数)──▶ 画面
promo.json (bpm, 小节, "bar:beat")           at() cue()          + score.py 在同一网格上写配乐
```

整个项目只做一件事：**把「声音走到哪」翻译成「第几帧该是什么样」**。有旁白的讲解片，声音是旁白；没有旁白的短片和广告，声音是配乐的节拍。下面每条原理，都是这条主线在某个方面的要求。

## 七条原理

### 1. 时间只有一个来源：声音

画面不自己计时，只问「这个 cue 在第几帧」。讲解片里 cue 落在旁白的字上：秒数只在 `gen.py` 产生，经 `timings.json` 进入画面，场景用 `c()` / `w()` / `rel()` 取帧。短片里 cue 落在节拍网格上：`promo/promo.json` 写 bpm 和每场几个小节，cue 写成「第几小节:第几拍」，场景用 `usePromo()` 的 `at()` / `cue()` 取帧，`tools/score.py` 在同一张网格上写配乐。

- **所以**：改一句旁白、换一个音色，重跑配音，动画和字幕自动对上；改 bpm，画面和音乐一起移动。写死的帧数会错位，按 cue 取帧的不会。
- **推论**：屏幕上的大字也该跟着声音走（`<Spoken>`）。「砸」下来的字要**落**在拍上，不是从拍上**开始**动：`land(f, at)` 是加速进场、恰好在 `at` 那一帧到位的进度，配 `<Sfx at={at}>`，画面和声音在同一帧撞上。转场同理：短片外壳让转场在下一场的重拍**之前**播放，重拍那一帧正好切完。

### 2. 每一帧是帧号的纯函数

同一个帧号，永远画出同一张图。不能用 `Math.random()`、当前时间，也不能把状态留到下一帧；需要随机就用 `rng(seed)`、`noise(seed, x)`。粒子（`<Burst>`）按抛物线公式从帧号算位置，不做逐帧积分。

- **所以**：渲染可以多进程乱序并行；审片工具可以直接跳到任意一帧；两次出片结果一致。
- **验证**：`npm run verify` 的第 4、6 关，把同一批帧渲染两次，逐字节比较。
- **注意**：审片工具出的图必须就是成片里的那一帧。讲解片的 `strip` 用 `<Freeze>` 冻结整片没问题；短片外壳的转场有预卷，用 `<Freeze>` 冻结会差出几帧，所以 `promo-sheet` 和 `verify` 对短片是逐帧直接渲染。

### 3. 动 = 进场 + 停留时的呼吸 + 退场

所有动效都是「一个 0→1 的进度」映射成样式：`tween` 算进度，`life(f, at, out)` 给出进场 `p` 和退场 `q`，`move(kind, p, q)` 变成 CSS。

- **所以**：画面问题都能归到这三段。死帧是停留阶段没有动作，加 `drift` 或让背景自己动；重影和重叠是旧内容没退场，补上 `out`；生硬是缺进度曲线，换 `EASE` 或弹簧。
- **推论**：能变形就别切（keynote 的 `Morph`）、容器先动内容后进、一个镜头最多停 1 秒，这些动效规则都是这一条的具体写法。落地以后的 `squash` 回弹也是「停留」的一部分。
- **快节奏的停留也要留够**：八分音符一张卡片的轮播，滑动只给 4 帧，剩下 3 帧静止、清晰；整段都在动，观众一个字也读不到。

### 4. 风格是外面那层衣服，核心不认识风格

场景只描述「什么时候出现什么」；底色、背景、叠加层、章节卡、字幕样式由 `Look` 统一套上；颜色经 `themed()` 暴露主色槽位。`src/core` 从不 import 任何风格包。

- **所以**：一场戏换一套风格，只改登记表里的 `look`；换品牌色只改 `kit.config.json`；删掉不用的风格包，其他代码不受影响。
- **推论**：新风格包一定要有 `themed()` 调色板、会动的背景、章节卡和 `Look`，`new-pack` 生成的骨架就是这四样。`punch` 包也是这样，所以它的组件既能放进讲解片的一场，也能放进短片。

### 5. 只在一张画布上设计，画幅交给外壳

讲解片的场景永远按 1920×1080 写。竖屏和方屏由 `Video` 外壳排版：中间放画面，上面是标题，下面是大字幕。

- **所以**：多一种画幅不用改任何场景；某场想在竖屏里放大，只在登记表里加 `portrait: {zoom}`。
- **代价**：竖屏里画面偏小。短片和广告是为手机做的，所以短片按自己的原生尺寸（`promo.json` 的 `width`/`height`，默认 1080×1920）单独设计，不走这层外壳。

### 6. 能由源文件推出来的，都不手改

`timings.json` 由 `gen.py` 生成，`public/sfx` 由 `sfx.py` 生成，配乐由 `music.py` / `score.py` 生成，logo 矢量由 `trace-logo.py` 从图片描出，成片由 `publish.mjs` / `promo.mjs` 一条命令产出。配置只在 `kit.config.json`（讲解片）和 `promo/promo.json`（短片）。

- **所以**：任何人、任何一台机器，拿到同一份仓库，就能出同一支片子。
- **验证**：`tests/test_sync.py` 检查旁白稿、时间轴、音频、登记表是否一致；`tests/test_sfx.py` 检查音效名、合成配方和文件是否一致；`tests/test_promo.py` 检查节拍网格、短片登记表、音效和广告文案。
- **logo 不找字体代替**：品牌的字标是设计过的形状，用相近字体打出来一眼就假。描出来（`tools/trace-logo.py`），按部件动画。

### 7. 声音是成品的一半，要量出来，不靠耳朵猜

画面有逐帧检查，声音也要有数：响度、真峰值、各段的起伏、各轨的平衡。

- **响度对齐用测量 + 线性增益 + 限幅**，不用单遍 `loudnorm`（它对短促有冲击力的素材会「抽」）：`tools/master.py` 测 → 加增益 → 前瞻限幅 → 再测，直到差 0.3 LU 以内。目标：短视频平台 -14 LUFS，网页视频 -16 LUFS。
- **真峰值在编码后的文件上测**：AAC 会把峰值抬高约 0.5 dB，WAV 上 -1.5 dBTP 的东西编码后可能超 -1；`master.py` 测成片，超了就降天花板重做。
- **平衡看数字**：`score.py` 按段打印每条总线的 RMS；混响冲击响应不做能量归一，湿声会比鼓大好几倍，整条声音糊成一片。`audio-report.py` 打印每一段的响度、画出波形和频谱：波形是一条平带说明压过头或混响糊了；铺垫段应该凹下去，重拍应该跳起来；某一场比邻居响 3 LU，就是那场的音效没配平（演示片 s08 的方波金币就是这样查出来的）。
- **验证**：`promo.mjs` 最后一步是 `audio-report.py --target`，真峰值超 -1 dBTP 或响度偏离目标 1 LU 以上就报错。

## 可交付、可重复、稳定输出

| | 在这个项目里的意思 | 靠什么保证 |
|---|---|---|
| **可交付** | 一条命令从仓库出成片，不依赖记忆和手工步骤 | `node tools/publish.mjs`（讲解片）、`node tools/promo.mjs`（短片）；`new-scene` / `new-pack` 生成能直接跑的代码 |
| **可重复** | 同样的输入，得到同样的输出 | 原理 2（纯函数）+ 原理 6（生成物有源）；素材全部由代码合成，依赖版本锁定 |
| **稳定输出** | 每次交付前都过同一道关，不靠运气 | `npm run verify`：类型 → 源文件一致 → 每场在每种画幅都能渲染 → 两次渲染逐字节一致 → 短片每个 cue 都能渲染 → 短片两次渲染一致；出片后响度和真峰值有报告 |

AI 写代码很快，但「快」只有落在这三条上才算数。这三条立住了，AI 加的每个功能都能被验收、能复现、能交给别人用。立不住，它每次都要从头猜一遍。

## 遇到新需求，先用原理推一遍

| 需求 | 从原理推 |
|---|---|
| 「这个图标要在说到某个词时亮起来」 | 原理 1：`w('那个词')` 拿帧号，`tween(f, 那一帧)` 做进度 |
| 「做一条 15 秒的广告，没有旁白」 | 原理 1：时间来源换成节拍。写 `promo/promo.json`（bpm、每场几小节、cue 落在哪一拍），场景用 `usePromo()`，`node tools/promo.mjs` 出片 |
| 「这个字要砸在鼓点上」 | 原理 1：`<Slam at={cue('hit')}>`（内部是 `land()`，在那一帧到位），同一帧放 `<Sfx name="impact">` |
| 「这段太平了」 | 原理 3：哪一段是空的？停留阶段加呼吸，切换时换一种进场方式或转场 |
| 「出一版抖音竖屏」 | 讲解片：原理 5，`npm run render -- 9x16`，内容太小就加 `portrait.zoom`；要原生竖屏的短片：用 promo |
| 「客户要用他们的品牌色和 logo」 | 原理 4：`brand.accent`；原理 6：`python tools/trace-logo.py logo.png` 描成矢量，`<LogoReveal>` 演出来 |
| 「声音听着糊」「平台上比别人小声」 | 原理 7：`python tools/audio-report.py 成片.mp4` 看平衡和响度，`score.py` 的总线 RMS 看是哪一轨 |
| 「广告文案能不能这么写」 | `python tools/copy_lint.py`：「最」「第一」「唯一」「100%」这类绝对化用语《广告法》第九条不许用 |
| 「渲染出来偶尔不一样」 | 原理 2：找随机数、时间、跨帧状态；`verify` 第 4、6 关会告诉你 |
| 「换了配音后动画错位」 | 原理 1：某处写死了帧数，改成 `c()` / `w()` / `rel()` |
| 「又在手动重复同一串操作」 | 原理 6：收成 `tools/` 脚本或补进 `.claude/skills/` |
